# MCP 서버 정리 (바이브 코딩 영상 트랜스크립트 기준)

> 출처: 영상에서 소개한 **9개 MCP**를 역할·대상·장단점·대안 중심으로 요약.  
> 핵심 메시지: **무조건 전부 설치 X**, CLI·문서로 되는 건 그쪽을 쓰고 **진짜 효율 나는 것만** MCP로 연결.

---

## MCP 한 줄 정의

- **MCP(Model Context Protocol)**: AI 코딩 클라이언트(Claude Code, Cursor, Codex 등)와 외부 서비스(GitHub, DB, Figma, Vercel 등)를 잇는 **범용 연결 표준**(영상 비유: AI 세계의 USB-C).
- 구성: **호스트(클라이언트 앱)** ↔ **MCP 서버(외부 서비스 래퍼)** ↔ **JSON 설정**으로 연결.
- 서버가 제공하는 것: **Tools**(AI가 실행하는 액션), **Resources**(AI가 읽는 데이터).

## 글로벌로 두루 추천 (영상 기준 “거의 필수”)

### 1. Context7

| 항목 | 내용 |
|------|------|
| **역할** | 질문 시 **학습 데이터가 아니라 현재 공식 문서**를 가져와 답변. 라이브러리·버전별 문서 검색. |
| **누구에게** | 거의 모든 프로젝트(영상: 글로벌 필수급). |
| **장점** | Next.js 등 “옛 문법 알려줌” 문제 완화. |
| **단점** | 문서가 잘 정리된 라이브러리에서만 효과 큼; 마이너·문서 부실 프로젝트는 제한적. |
| **주의** | 프롬프트에서 Context7을 **언급하지 않으면** 에이전트가 무시할 때가 있음. |
| **대안** | 영상 표현: “대안이 아니라 기본값” — **안 깔 이유가 없다** 수준. |

### 2. Playwright MCP (Microsoft 공식)

| 항목 | 내용 |
|------|------|
| **역할** | AI가 **Chromium에서 직접** 페이지 열기·탐색·클릭·검증. |
| **누구에게** | 프론트 기능 검증이 잦은 경우; Claude Code 등 **내장 브라우저 없는** 흐름과 궁합. |
| **장점** | 스크린샷보다 **접근성 트리 기반**이라 빠르고 정확, 토큰 절약. 로컬호스트 로그인 플로우 등. |
| **단점** | **로컬 개발 서버가 떠 있어야** 함. **시각적 디자인/CSS 깨짐**은 사람+스크린샷이 나을 수 있음. |
| **대안** | 수동 스크린샷 확인; Claude Code는 스크린샷 입력 가능. **Antigravity 등 내장 브라우저** 있으면 필수는 아님. |

## 프로젝트·상황별 선택 (범용성 기준 별점 언급 수준)

### 3. GitHub MCP (GitHub 공식)

| 항목 | 내용 |
|------|------|
| **역할** | 코드 검색, PR·이슈 관리 등 GitHub 작업을 AI가 직접. |
| **누구에게** | 팀·오픈소스·PR 리뷰가 잦은 경우. **MCP JSON으로 팀 공유**는 장점. |
| **단점/메모** | **Claude Code + `gh` CLI**면 비슷한 일 많이 가능 → **편의·자동 참조** 차이. 개인 소규모는 굳이 느낄 수 있음. |

### 4. Figma MCP (Dev Mode, 공식 계열)

| 항목 | 내용 |
|------|------|
| **역할** | 피그마 **레이어·오토레이아웃·텍스트 스타일·디자인 토큰** 등 구조화 데이터 → 코드 생성 정확도↑. |
| **누구에게** | 디자이너 협업 FE, 디자인 시스템이 정리된 팀. |
| **단점** | **유료(Professional 이상)**. 레이어 이름이 `Frame 237` 수준이면 AI도 한계. **복잡한 인터랙션·애니메이션**은 사람 주도가 낫다고 언급. |
| **대안** | 스크린샷 + 상세 프롬프트(간단 UI는 가능). |

### 5. Sequential Thinking MCP

| 항목 | 내용 |
|------|------|
| **역할** | 외부 연결이 아니라 **문제 분해·대안 탐색·계획 수정** 등 “사고 과정” 보조. |
| **누구에게** | 인증 마이그레이션급 큰 작업, 아키텍처 변경, 큰 리팩터링. |
| **단점** | 체감 미묘할 수 있음; Claude Code **extended thinking / plan 모드**와 겹침. **Opus 4.6** 등 모델 강화로 필요성 감소 가능. |
| **대안** | **Plan MD + 어노테이션 사이클**(사람+AI 협업)이 더 나은 경우도 많다고 언급. |

### 6. Supabase / “DB 입출력 MCP” 일반화

| 항목 | 내용 |
|------|------|
| **역할** | 스키마 확인·쿼리 실행 등 DB를 AI가 직접 다룸. |
| **누구에게** | **경험 있는 개발자**가 스키마 확인·쿼리 테스트용(읽기 위주)으로는 “편의”. |
| **위험** | DB를 모른 채 전부 맡기면 **슬로우 쿼리·N+1** 등 운영 이슈 시 원인 파악 비용↑. **동작하는 쿼리 ≠ 효율적인 쿼리**. **프로덕션 쓰기**는 사고 위험 — **읽기 전용 계정** 강조. |
| **대안** | 스키마를 **마크다운으로 repo에 두기** — 느리지만 이해도 유지. Plan MD 기반 자기 주도 워크플로와 맥락이 비슷하다고 언급. |

### 7. Vercel MCP

| 항목 | 내용 |
|------|------|
| **역할** | 배포 상태, 빌드 로그, 환경 변수, 프로젝트 관리 등. |
| **누구에게** | Vercel 프로젝트 여러 개·환경 변수 자주 바꾸는 팀. |
| **단점** | **Vercel CLI**로 대부분 가능; “AI가 자동 참조” vs “한 마디 더 지시” 차이. 배포를 AI에만 맡기면 **파이프라인 감각**이 무뎌질 수 있음. 초보는 CLI·대시보드로 먼저 체득 권장. |
| **메모** | Netlify도 CLI로 비슷한 이야기. |

### 8. Sentry MCP

| 항목 | 내용 |
|------|------|
| **역할** | 프로덕션 에러·스택 트레이스·릴리즈 연관 분석을 AI가 직접. |
| **누구에게** | **이미 Sentry 쓰는** 프로덕션 운영 팀. |
| **단점** | Sentry 미사용이면 무의미. AI는 **증상 수정**에 치우치기 쉽고 **반복 패턴**은 사람이 낫다고 언급. |
| **대안** | 대시보드에서 에러 URL 복사해 모델에 붙이기. |

### 9. Serena MCP (오픈소스 코딩 에이전트 툴킷)

| 항목 | 내용 |
|------|------|
| **역할** | **MCP + LSP**로 IDE급 탐색(정의로 이동, find references, 심볼 단위). 인덱스 후 **필요한 코드만** 읽어 토큰·속도·품질 이점. |
| **누구에게** | **대규모 코드베이스**; 특히 **Claude Code**(자체 인덱싱 약함)와 시너지. **Cursor는 자체 인덱싱**이 있어 상대적으로 덜 필수적이라고 언급. |
| **단점** | 설치 복잡(Python, 언어별 LSP). **소규모 프로젝트는 오버킬**. 언어별 성숙도 차이(Python/TS 안정, 일부는 커뮤니티 수준). |
| **대안** | CLAUDE.md / Plan MD에 구조·주요 파일 위치 정리; 규모 커지면 한계 → 그때 Serena 검토. |

## 보안·운영 주의 (영상 마무리)

- **읽기 전용**으로 시작; 특히 DB **프로덕션 쓰기**는 위험.
- **API 키를 JSON에 직접** 넣지 말고 **환경 변수** 등으로 관리; MCP JSON **git 커밋 시 토큰 노출** 주의.
- **프로덕션 vs 개발** 분리. MCP는 편하지만 **한 줄 설정으로 사고** 가능성도 있다고 강조.

---

## 총정리 한 줄

- **“계획 먼저” 다음 단계로 AI에 눈·손을 달되, 꼭 필요한 만큼만.** CLI·문서로 되는 건 그쪽을 유지하고, **진짜 자동화 이득이 큰 것만** MCP로 연결하는 것이 영상의 결론에 가깝다.

---

## MCP의 방향(영상 후반)

- 현재는 **사람이 AI에 MCP를 연결**하는 구조이지만, 앞으로는 **에이전트가 필요한 MCP를 스스로 찾아 연결·해제**하는 흐름이 올 수 있다는 전망이 언급됨.
